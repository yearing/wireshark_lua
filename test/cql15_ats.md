# 工作范围划分

## 网络全局调度系统工作范围

1. 负责实施接口的功能测试及联合调试；
2. 配合综合监控系统接口的安装与施工；
3. 配合综合监控系统供货商的连接测试；
4. 与对方协商后共同确定统一的接口传输协议；
5. 坐席管理系统使用部分的显示画面的设计及实施，并提供相关软件及数据，以完成信号画面在坐席管理系统上的显示，并负责完成相关软件及画面的安装调试；
6. 大屏幕显示信号系统用部分的显示画面的设计及实施，以完成信号画面在大屏幕上的显示，并负责完成画面的安装调试；
7. 配合坐席管理系统的功能测试及联合调试。

5. 负责联合调试；
6. 配合网络全局调度系统供货商的接口功能测试及联合调试。

# 接口界面划分

网络全局调度系统与综合监控系统的接口位置位于控制中心、备用系统，无直接物理接口，网络全局调度系统与综合监控系统通过控制中心设备系统内部接口实现信息交互。

从综合监控系统到网络全局调度系统的接口是冗余的（正常/备用）虚拟通道连接。

# 接口协议

## 原则

网络全局调度系统和ISCS系统之间将采用虚拟网口连接进行信息交换。它们之间的数据传输是双向的， 网络全局调度系统系统和ISCS系统双向收发数据。

1. 当网络全局调度系统重启或ISCS重启时（即通道重新激活后），双方主动向对方发送一次全体信息。
2. 如果SCADA状态有变化，ISCS发送全部的SCADA 信息至网络全局调度系统（网络全局调度系统），如果信息在5秒钟内不变化，也发送全部信息给SIG（网络全局调度系统）系统。
3. 如果车站（含段场）火灾、区间火灾状态有变化，ISCS发送全部的FAS火灾信息至网络全局调度系统（网络全局调度系统），如果信息在5秒钟内不变化，则也发送全部信息给SIG（网络全局调度系统）系统。
4. 如果区间超高水位状态有变化，ISCS发送全部的区间超高水位信息至网络全局调度系统（网络全局调度系统），如果信息在5秒钟内不变化，也发送全部信息给SIG（网络全局调度系统）系统。
5. 信息发送采用变化发送的方式，初始建立连接的时候发送全体信息，若信息改变，则立刻发送。
6. 当主机收到一条信息时，必须立即向发送方发送一条回执信息。数据发送方接收到回执信息后，必须立即发送下一包数据。为了保证数据及时下发，数据接收方需要有每秒接收30包信息，并发送30包回执信息的处理能力。

与坐席管理系统接口协议：

在控制中心采用TCP/IP网络协议，X-Window通信协议为X11R6。信号系统将发送数字信号给大屏幕系统。数据传输是单向的，仅从网络全局调度系统到DLP。

### 数据发送原则

站台信息由网络全局调度系统发送，站台信息最大可为未来60分钟内到站的列车发送信息。

每辆列车的规划周期为60分钟，例：每列列车都应有一个计划包含了未来60分钟制定好的运行。根据针对每列列车未来60分钟运行而生成的计划，站台信息将发送给所有列车计划中涉及到的站台。例如，系统中只有一辆列车，并且他将在首站停留1分钟，那么就有一个当前站台之后未来59分钟的列车计划。在这种情况下，如列车在1分钟后离开首站，那些列车在59分钟后未能到达的车站就不应显示该列列车。

一个站台可接受多于一辆列车的信息。根据每一列车的情况生成一个将来60分钟的运行计划，对各站台来说这是列车运行计划，站台信息将被发送给站台。站台信息中包含的各列车无到站时间先后顺序。

站台信息将在以下情况下发送：

* 如果某一重大事件影响了列车计划，如，一列列车进入或离开系统。每列列车的计划周期为未来的60分钟。
* 当站台数据变化时，会发送至ISCS。

如果没有变化情况，站台信息只发送一次。当检测到某个站台有变化信息时，网络全局调度系统将发送会到达该站台的所有列车的最新信息。ISCS应使用该站台列车的最新信息。如果先前ISCS系统具有某辆车的到站信息，并且最新接收到的信息中不再包含此车，那么说明此车的计划已不包含该站台，应被移除。

ISCS系统发送给SIG（ATS）的客流信息，采用定时的发送方式，每60s（暂定）发送一次全部信息给信号系统（ATS）。当ISCS重启或连接刚建立时，发送全部数据至SIG（ATS）。

# 通信机制

## 建立连接

网络全局调度系统与ISCS系统采用控制中心系统内部虚拟通道进行连接。网络全局调度系统与ISCS之间有6个逻辑通信连接。

网络全局调度系统为ISCS系统提供4个IP地址，ISCS提供4个相应的端口分别对应控制中心和备用中心的ISCS服务器。

网络全局调度系统系统为服务端，ISCS作为客户端进行连接。网络全局调度系统提供6个IP地址，通讯建立时ISCS应试图连接第一个IP地址，一旦连接已经建立，ISCS不会建立其他连接。但是ISCS的连接应处于备用状态，随时准备进行连接。

如果由于某种原因，ISCS与网络全局调度系统的第一个IP地址的连接没有建立成功，ISCS应试图连接到第二个IP地址、第三个IP地址、第四个IP地址、…..，直到成功建立连接。

正常情况下控制中心的网络全局调度系统服务器作为主用服务器，当控制中心主备网络全局调度系统服务器都不可用时，系统将自动切换到备用控制中心的网络全局调度系统服务器上使用。

## 信息传送

信息通过已经建立的连接进行传送。

## 保持连接

有效链接上，当无数据发送时，双方每1秒钟互发心跳信息，在3次心跳时间内没有收到任何数据或心跳信息则认为链接失效。ISCS应尝试新的连接。

## 通道故障切换处理

网络全局调度系统系统作为服务器端，ISCS作为客户端进行连接。

成功建立的连接作为主用通道，其它为备用通道且未连接。网络全局调度系统系统与ISCS系统通过主用通道相互发送信息。

如果主用通道连接故障，ISCS应尝试与其它的IP地址建立连接，一旦连接建立，信息通过刚刚建立的连接传送，此通道变为主用通道。

# 接口特性要求

接口要求：符合标准TCP/IP协议。

从信号交换机到ISCS采用控制中心系统虚拟网络通道。

从信号系统交换机到大屏控制器的物理连接是以太网线。

接口电缆：标准网线；

连接端口：

网络全局调度系统侧 – RJ45

# 接口测试

为了确保ISCS和网络全局调度系统的接口的正确性、完整性、实时响应能力，必须进行充分的接口测试，检验ISCS和网络全局调度系统接口部分的功能、性能是否达到设计要求。

为了确保坐席管理系统和网络全局调度系统的接口的正确性、完整性、实时响应能力，必须进行充分的接口测试，以达到预期的良好的系统性能。

现场测试应该在坐席管理系统和网络全局调度系统设备现场安装和内部测试完成之后进行。

接口的测试工作需要信号系统供应商与坐席管理系统供应商相互配合完成及共同确认。

以下是CRC校验算法

/\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*

计算校验和函数

buf : 缓冲区

len : 数据长度

low: 校验和第二个字节

Calculate the checksum function

Buf:buffer

Len: data length

High: The first byte checksum

low:The second byte checksum

\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*/

unsigned char CalCRC(unsigned char\* buf, int len, unsigned char& high, unsigned char& low)

{

int crc = 0;

for (int i = 0; i< len; ++i)

{

crc += buf[i];

}

unsigned char \_crc = crc & 0xFF;

high = \_crc/16;

low = \_crc%16;

if (high<=9)

{

high += 0x30;

}

else if (high>=10 && high<=15)

{

high += (0x41-0x0a);

}

if (low<=9)

{

low += 0x30;

}

else if (low>=10 && low<=15)

{

low += (0x41-0x0a);

}

return \_crc;

}
