## 协议定义

### 通信协议

网络协议采用UDP协议，双方使用一对端口分别进行数据的传输，通信端口从配置文件读出（可配置）。ISCS服务器默认信令接收端口为18010，地面PIS默认信令接收端口为18030。

应用协议采用自定义格式，格式及消息定义见3.2.2及以后章节定义。

### 消息格式

**消息格式：**

|  |  |  |  |  |  |  |  |
| --- | --- | --- | --- | --- | --- | --- | --- |
| **数据帧头** | **消息序号** | **设备序号** | **消息类型** | **起始地址** | **消息内容** | **包校验** | **数据帧尾** |
| 1Byte | 1Byte | 1Byte | 1Byte | 2Byte | N Bytes | 1Byte | 1Byte |

**数据帧头：**

固定为0x7F;

**消息序号:**

0~255，每发一包数据加1，255后下一个序号为0;

**设备序号:**

列车目前取值1~25, ISCS系统取值为0xF0,PIS服务器取值为0xF5

**消息类型：**

标记该消息类型，取值如下：

|  |  |  |
| --- | --- | --- |
| **序号** | **取值** | **消息类型** |
|  | 0x01 | 会话建立信令，ISCS发往PIS |
|  | 0x02 | 心跳信令，PIS发往ISCS |
|  | 0x04 | 确认报文，收到数据后发往对方 |
|  | 0x10 | 数据信令，PIS 发往ISCS |
|  | 其他 | 预留 |

**起始地址：**

仅对数据信令有效，其余为0，分别为点表的起始地址,取值为30的整倍数。

**消息内容：**

仅对数据信令有效，其余空，从起始地址开始的30个字节内容。

**包校验：**

从消息序号开始到消息内容结束的数据

**数据帧头：**

固定为0x7E;

**发送字节序顺序：**

对于2个或者4个字节的整数字段，按照网络字节序发送，即大端在前小端在后，例如，消息如果为0x0102，那么发送数据应该是“0x01 0x02”。

### 消息定义（含消息类型及消息内容）

#### 会话建立信令

##### 通信流程

ISCS系统在启动时，向PIS服务器发送会话建立信令，在没有收到PIS回复0x04消息或0x02消息，每隔固定周期（可设置范围为2-30，默认取值为5秒）主动继续发送此消息给PIS系统。PIS系统收到该消息，会回复0x04消息给综合监控系统，并向该信令指定的服务器发送数据信令。

PIS系统收到新的初始化信令，会把数据消息发往新消息指定的服务器。PIS系统只保留最终收到的接收数据地址。

ISCS系统收到PIS系统的0x04信令或0x02信令，不再继续发送该消息。

##### 信令内容（ISCS发送至PIS）

|  |  |  |
| --- | --- | --- |
| **字段说明** | **字节长度** | **值（HEX）** |
| 设备序号 | 1 | 0xF0 |
| 消息类型 | 1 | 0x01 |
| 起始地址 | 2 | 0x00,0x00 |
| 消息内容 | 4 | 用4个字节传递ISCS系统的IP地址：A.B.C.D  字节1：A  字节2：B  字节3：C  字节4：D |

例如ISCS系统的前置机IP为192.168.0.1则信令如下：

0x7F,0x01,0xF0,0x01,0x00,0x00,0xC0,0xA8,0x00,0x01,0x5B,0x7E

一共12个字节，其中0xC0,0xA8,0x00,0x01,表示的就是192.168.0.1

校验和为 0x01+0xF0+0x01+0x00+0x00+0xC0+0xA8+0x00+0x01=0x25B，取最后单一字节为0x5B。

##### 回复消息（PIS发送至ISCS）

|  |  |  |
| --- | --- | --- |
| **字段说明** | **字节长度** | **值（HEX）** |
| 消息序号 | 1 | 同信令数据 |
| 设备序号 | 1 | 0xF5 |
| 消息类型 | 1 | 0x04 |
| 起始地址 | 2 | 0x00，0x00 |
| 消息内容 | 1 | 0x01， 确认收到 |

对上一报文的回复就为

0x7F,0x01,0xF5,0x04,0x00,0x00,0x01,0xFB,0x7E

一共9个字节。

检验和为0x01+0xF5+0x04+0x00+0x00+0x01=0xFB

#### 心跳信令

##### 通信流程

当PIS系统收到会话建立信令之后，每隔5秒定时向ISCS指定IP发送心跳信令，作为ISCS对PIS的连通性判断。

ISCS系统收到心跳信令后回复0x04确认消息。

##### 心跳信令（PIS发送至ISCS）

|  |  |  |
| --- | --- | --- |
| **字段说明** | **字节长度** | **值（HEX）** |
| 设备序号 | 1 | 0xF5 |
| 消息类型 | 1 | 0x02 |
| 起始地址 | 2 | 0x00,0x00 |
| 消息内容 | 0 |  |

PIS发送的数据如下（以消息序号为6举例）：

0x7F,0x06,0xF5,0x02,0x00,0x00,0xFD,0x7E

一共8个字节。（以下不再计算检验和）

##### 回复消息（ISCS系统发送至PIS）

|  |  |  |
| --- | --- | --- |
| **字段说明** | **字节长度** | **值（HEX）** |
| 消息序号 | 1 | 同信令数据 |
| 设备序号 | 1 | 0xF0 |
| 消息类型 | 1 | 0x04 |
| 起始地址 | 2 | 0x00，0x00 |
| 消息内容 | 1 | 0x01， 确认收到 |

对上一报文的回复就为

0x7F,0x06,0xF0,0x04,0x00,0x00,0x01,0xFB,0x7E

一共9个字节。

#### 数据信令

##### 通信流程

Pis系统收到车载上传的状态数据立即转发至ISCS。

ISCS系统收到后回复0x04信令。

##### 信令内容（PIS发送至ISCS）

|  |  |  |
| --- | --- | --- |
| **字段说明** | **字节长度** | **值（HEX）** |
| 设备序号 | 1 | 1~25，为列车序号 |
| 消息类型 | 1 | 0x10 |
| 起始地址 | 2 | 从0开始至2130，均为30的整倍数 |
| 消息内容 | 30 | 从起始地址开始的30个字节数据 |

起始地址取值为0，30，60，90，120……2100，2130，2130。

2100以后点表无对应值，可进行忽略。

第一个注意要点为设备序号为列车序号。

第二个注意要点为发送包的顺序起始地址不是连续的。发送30后多半为90。

##### 回复消息（ISCS系统发送至PIS）

|  |  |  |
| --- | --- | --- |
| **字段说明** | **字节长度** | **值（HEX）** |
| 消息序号 | 1 | 同信令数据 |
| 设备序号 | 1 | 0xF0 |
| 消息类型 | 1 | 0x04 |
| 起始地址 | 2 | 0x00，0x00 |
| 消息内容 | 1 | 0x01， 确认收到 |

一共9个字节。同3.3.3.2.3。
